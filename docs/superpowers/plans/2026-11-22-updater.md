# In-App Updates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tray **Check for updates** and an opt-in **Check automatically** install signed, published GitHub releases in place.

**Architecture:** `updates.rs` holds the pure rules (saved settings, is a check due). `updater.rs` drives `tauri-plugin-updater` off the main thread and asks through the tray's message boxes. `scripts/latest-json.mjs` builds the release manifest for `release.yml`, which signs the installer with repository secrets.

**Tech Stack:** Tauri 2.12, tauri-plugin-updater 2, Node 22 (manifest script), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-22-updater-design.md`

## Global Constraints

- Endpoint: `https://github.com/jbstinson/DesktopAssistant/releases/latest/download/latest.json`.
- Windows install mode is `passive`. The app always asks before installing.
- **Check automatically** is off by default; a missing or broken `updates.json` means off. No network request unless auto is on and a check is due, or the user clicked **Check for updates**.
- A check is due when auto is on and `last_check` is missing or at least 86400 seconds ago. While running, re-check every 24 h.
- Release secrets: `TAURI_SIGNING_PRIVATE_KEY`, `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`. Missing secrets fail the release job.
- Never use the real signing key in tests. Local tests use a throwaway key pair in the scratchpad.
- New `src-tauri/src/*.rs` files are added to the source-file list in `permission.rs` (and its array length bumped).

## Review Focus

- `updates.json` missing, empty or not JSON: auto is off and nothing is contacted (Task 1 tests).
- Clock moved backwards (`last_check` in the future): treat it as due, so a broken clock can't stop checks forever (Task 1 test).
- Offline or GitHub unreachable: a manual check shows the error; an automatic check stays silent and doesn't update `last_check` (Task 3, manual check).
- A tampered signature: the update is refused and the app keeps running (Task 3, local check).
- Clicking **Check for updates** twice quickly: only one check runs (Task 3).

### Task 1: Update settings and the due rule

**Files:** Create `src-tauri/src/updates.rs`; modify `src-tauri/src/main.rs` (`mod updates;`), `src-tauri/src/permission.rs`.

**Interfaces (produces):**
- `pub struct UpdateSettings { pub auto: bool, pub last_check: Option<u64> }` (serde, `Default` is off/None).
- `pub fn load(path: &Path) -> UpdateSettings`, `pub fn save(path: &Path, s: &UpdateSettings) -> std::io::Result<()>` (atomic temp+rename, like `avatar::save`).
- `pub fn is_due(s: &UpdateSettings, now: u64) -> bool`.
- `pub const DAY_SECS: u64 = 86400;`

  - `due_after_a_day_not_before`: `last_check` = now−86399 is false; now−86400 is true.

### Task 2: Release manifest script

**Files:** Create `scripts/latest-json.mjs` and `scripts/latest-json.test.mjs`.

**Interfaces (produces):**
- `export function latestJson({ version, notes, pubDate, signature, url })` returns `{ version, notes, pub_date: pubDate, platforms: { "windows-x86_64": { signature, url } } }`. It throws if any field is empty, and strips a leading `v` from `version`.
- CLI: `node scripts/latest-json.mjs <version> <sig-file> <url> <out-file>` writes the manifest (notes: `"See the release page."`, pubDate: now in ISO format). Task 4 calls it.

- [ ] Tests:
  - `builds_the_windows_entry`
  - `strips_a_leading_v`
  - `refuses_missing_fields`: an empty signature throws.
- [ ] Implement, run `node --test scripts/*.test.mjs`, commit `feat: latest.json builder for update releases`.

### Task 3: Plugin, tray items and the check flow

**Files:** Create `src-tauri/src/updater.rs`; modify `src-tauri/Cargo.toml` (`tauri-plugin-updater = "2"`), `src-tauri/tauri.conf.json` (`plugins.updater`: `pubkey`, `endpoints`, `windows.installMode: "passive"`), `src-tauri/src/main.rs` (register the plugin, the startup check and the 24 h timer), `src-tauri/src/tray.rs` (items `updates` "Check for updates" and `updates-auto` "Check automatically", plus an `info` message box helper), `permission.rs`.

**Interfaces:**
- Consumes: Task 1.
- Produces: `pub fn check(app: &AppHandle, manual: bool)`. It returns at once and runs on `tauri::async_runtime`. A static `AtomicBool` stops overlapping checks. On success it saves `last_check`.
  - **No update:** a manual check shows "You have the latest version (X)"; an automatic one stays silent.
  - **An update:** `ask("DesktopAssistant {new} is available (you have {current}). Install it now?")`. On yes: download, then remove `endpoint.json` (as `tray::quit` does), then install. The plugin exits the app and the setup restarts it.
  - **Error:** a manual check shows the error; an automatic one only logs it.

- [ ] **Throwaway key:** `npx tauri signer generate --ci -p "" -w <scratchpad>/upd-test.key`. Put its public key in `tauri.conf.json` for now. The owner's real public key replaces it before merging.
- [ ] Implement. `cargo test --workspace --locked` passes.
- [ ] **Local end-to-end with the throwaway key:**
  1. Build v0.1.0's setup with the endpoint overridden to `http://127.0.0.1:8770/latest.json`, using a `--config` overlay in the scratchpad that also sets `plugins.updater.dangerousInsecureTransportProtocol: true`.
  2. Install it to a scratch folder.
  3. Build v0.1.1 the same way, signed.
  4. Serve `latest.json` (from Task 2's CLI) and the setup locally.
  5. Run the installed v0.1.0 and click **Check for updates**, then **Yes**. Expect the app to restart as 0.1.1 in the same folder.
  6. Repeat with a tampered `.sig`. Expect an error dialog and the app still running.
- [ ] Commit `feat: check for updates from the tray (automatic checks are opt-in)`.

    - back up the private key
